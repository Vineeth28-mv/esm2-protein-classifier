# ESM-2 Protein Classifier

Train a classifier on top of the **ESM-2 protein language model** using **your own protein classes**, then use it to label new sequences.

Give it FASTA files where each header carries a label (for example `familyX` vs `other`, or 20 functional categories) and it will:

1. turn every protein into an ESM-2 representation, **once**, and cache it on disk,
2. train a small classification head on those representations (ESM-2 itself stays frozen),
3. evaluate every epoch, keep the best model, and
4. write a full set of results: metrics, a confusion matrix, per-sequence probabilities and plots.

Because embeddings are cached, re-training with different labels, epochs, learning rate or pooling method on the same sequences takes seconds instead of hours.

It is a general version of the training pipeline built for mobileOG-db, with no mobileOG-specific labels in the code. A typical question it answers: **"Does ESM-2 capture protein family X well enough to tell it apart from other proteins?"**

## Quick start

```bash
git clone https://github.com/<your-github-username>/esm2-protein-classifier.git
cd esm2-protein-classifier

# Install (a fresh conda or venv environment is recommended)
pip install -r requirements.txt

# Train on the small demo dataset (runs on a laptop CPU in a few minutes)
python train.py --config config.yaml

# Predict with the trained model
python predict.py --model results/example_run/best_model \
                  --fasta example_data/unlabelled.fasta \
                  --out results/example_run/unlabelled_predictions.csv
```

The first run downloads the ESM-2 weights from Hugging Face (about 30 MB for the default 8M model).

> **Note:** the demo data in `example_data/` is **synthetic** (generated by `example_data/make_toy_data.py`). It only checks that everything runs. Do not interpret its results biologically.

## Preparing your data

You need **FASTA files whose headers contain the label after a `|`**:

```text
>WP_012345678.1|familyX
MKKLLIVSAALLAGCSQ...
>WP_098765432.1|other
MSNQEIRVLLVDDHPLV...
```

- Everything before the first `|` is the sequence ID; the part after it is the label. (A different separator or field can be set with `--label-delimiter` / `--label-field`.)
- Labels can be any text without spaces or `|`, for example `familyX`, `integrase`, `class_3`.
- You need **at least two classes**. A typical feasibility test is binary: your family vs. a background set.
- Stop codons (`*`) are removed automatically wherever they occur (`ANPP*NNNN` → `ANPPNNNN`), and sequences are upper-cased. Sequences with a `*` in the middle are listed in the log so you can check them.

Provide:

| File | Required? | Purpose |
|---|---|---|
| training FASTA | yes | the model learns from these |
| test FASTA | yes | final, independent evaluation |
| validation FASTA | optional | used to pick the best epoch (see below) |

**Split your data by sequence similarity, not at random.** If near-identical proteins end up in both training and test, the scores will look much better than the model really is. Cluster first (for example with MMseqs2 at 30–80% identity) and put whole clusters into each split. See [docs/data_format.md](docs/data_format.md) for a step-by-step recipe and advice on building a good negative ("other") set.

## Training

```bash
python train.py --config config.yaml \
    --train data/train.fasta \
    --val   data/val.fasta \
    --test  data/test.fasta \
    --out   results/familyX_run1
```

Any setting in `config.yaml` can be overridden on the command line. Run `python train.py --help` for all options.

### How the best epoch is chosen

Every epoch is evaluated, and the one with the highest **MCC** is kept (you can change the metric with `--selection-metric`).

| You provide | Best epoch is chosen on | Test set is used |
|---|---|---|
| `--val` file | validation set | once, for the chosen epoch only |
| no validation file (`--no-val`, or `val: null` in the config) | test set | for every epoch |

Without a validation set, the selected epoch's test scores can be slightly optimistic, because the same data was used to choose and to report. The outputs say so explicitly, and they also report the **final epoch's** test scores next to the best ones so you can see the difference. With a large, independent test set and a flat curve across epochs, the difference is usually negligible.

### What is being trained

The ESM-2 backbone is **frozen**; only the small classification head on top is trained (about 100,000 parameters for the 8M model, up to about 1.6 million for the 650M model). The loss is **class-weighted** cross-entropy (`class_weighting: balanced`), so rare classes are not ignored. See [docs/how_it_works.md](docs/how_it_works.md) for a plain-language explanation.

## Pooling: `cls` or `mean`

ESM-2 outputs one vector per amino acid. The classifier needs one vector per protein, and there are two ways to get it:

| `--pooling` | Protein vector | Notes |
|---|---|---|
| `cls` (**default**) | the vector of the special `<cls>` start token | what Hugging Face's `EsmForSequenceClassification` uses, and the method of the original mobileOG pipeline |
| `mean` | the average of all residue vectors (start/end tokens and padding excluded) | the standard per-protein ESM embedding; often better with a frozen ESM-2 |

ESM-2 was trained only to predict hidden amino acids; the `<cls>` token was never trained to summarise the protein. With a frozen ESM-2, published comparisons generally find mean pooling equal or better (see [docs/how_it_works.md](docs/how_it_works.md#2-from-a-protein-to-one-vector)). The default stays `cls` so results reproduce the original pipeline; **we recommend running both** and comparing MCC:

```bash
python train.py --config config.yaml --pooling cls  --out results/familyX_cls
python train.py --config config.yaml --pooling mean --out results/familyX_mean
```

Both vectors are computed and cached in the same pass, so the second run reuses the embeddings and only trains the head.

## Embedding cache

Because ESM-2 is frozen, each protein's embedding never changes. `train.py` therefore runs ESM-2 **once per sequence**, saves the results in `embedding_cache/`, and trains the head on those stored vectors. This gives exactly the same model as running ESM-2 inside every training step, but much faster.

- The cache key is the **ESM-2 model + `max_length` + numeric precision (fp16/fp32) + the sequences themselves**. Changing labels, epochs, learning rate, class weighting, pooling or the selection metric all reuse the cache. Changing the model, `max_length` or any sequence computes new embeddings.
- Size: about `number of sequences × 2 × hidden size × 4 bytes`, e.g. ~2.5 GB per million sequences for the 8M model (hidden size 320) and ~10 GB per million for 650M (hidden size 1280). Old cache files can be deleted at any time; they are recomputed when needed.
- Use `--cache-dir` to put the cache elsewhere (e.g. scratch storage on a cluster), or `--no-cache` to disable it.

## Predicting new sequences

```bash
python predict.py --model results/familyX_run1/best_model \
                  --fasta new_proteins.fasta \
                  --out predictions.csv
```

**Any header format works.** By default the whole header word is kept as the sequence ID, so files downloaded from UniProt (`>sp|P0A7V8|RS4_ECOLI ...`) can be used as they are, and every row of the output stays identifiable.

**To check the model on a labelled file** (`>seqID|label`) and get MCC, F1 etc., add `--labelled`:

```bash
python predict.py --model results/familyX_run1/best_model --fasta test.fasta \
                  --out test_predictions.csv --labelled
```

With `--labelled`, labels are read the same way as in training (the label format is saved with the model). The pooling method, `max_length` and numeric precision used in training are also read from the model folder automatically (override the precision with `--fp16` / `--no-fp16`).

The saved model stores only the trained head (small) plus the name of the ESM-2 model, which is loaded from Hugging Face (or its local cache) when `predict.py` runs. To make the model folder self-contained, e.g. for an offline cluster node or another computer, train with `--save-backbone` to copy ESM-2 into it.

The CSV has one row per sequence:

| seq_id | predicted_label | confidence | prob_familyX | prob_other |
|---|---|---|---|---|
| query_01 | familyX | 0.97 | 0.97 | 0.03 |

`confidence` is the probability of the predicted class. It is useful for ranking but is not a calibrated probability (see [docs/interpreting_results.md](docs/interpreting_results.md)).

## Outputs

Everything is written to the folder given by `--out` (default from `config.yaml`):

| File | What it contains |
|---|---|
| `summary.json` | headline test metrics, best and final epoch, and how the best epoch was chosen |
| `epoch_results.csv` | MCC, accuracy, and macro- and weighted-averaged precision, recall and F1 for every epoch; `selected` marks the best one |
| `epoch_metrics.png` | MCC and accuracy across epochs |
| `training_loss.png` | training loss curve |
| `classification_report.txt` | per-class precision, recall and F1 on the test set, plus macro and weighted averages |
| `confusion_matrix.csv` / `.png` | where the model confuses classes |
| `predictions_test.csv` | every test sequence with true label, prediction, confidence and probability per class |
| `best_model/` | the trained head, tokenizer and settings (pooling, model name, classes), for use with `predict.py` |
| `run_config.yaml` | the exact settings used, for reproducibility |
| `training_log.json` | raw training log |

Precision, recall and F1 are reported two ways: **macro** (every class counts equally; the recommended headline, together with MCC) and **weighted** (classes count in proportion to their size). See [docs/interpreting_results.md](docs/interpreting_results.md) for when to use which.

## Configuration

All settings live in [`config.yaml`](config.yaml) and are documented there. The most useful ones:

| Setting | Default | Meaning |
|---|---|---|
| `model.name` | `facebook/esm2_t6_8M_UR50D` | which ESM-2 model to use |
| `model.max_length` | `1024` | max tokens (3–1024; ESM-2 was trained on at most 1024); proteins longer than 1022 aa are truncated (a note is printed) |
| `model.pooling` | `cls` | `cls` or `mean` (see [Pooling](#pooling-cls-or-mean)) |
| `embeddings.cache_dir` | `embedding_cache` | where embeddings are cached; `null` disables caching |
| `embeddings.batch_size` | `32` | sequences per batch for ESM-2; lower it if the GPU runs out of memory |
| `embeddings.fp16` | `auto` | half precision for ESM-2 on a GPU: `auto`, `true` or `false` (always full precision on a CPU) |
| `training.epochs` | `10` | number of epochs |
| `training.learning_rate` | `1e-3` | suitable for a frozen backbone |
| `training.batch_size` | `16` | batch size for training the head |
| `training.class_weighting` | `balanced` | `balanced` or `none` |
| `training.selection_metric` | `mcc` | metric used to pick the best epoch (e.g. `mcc`, `f1_macro`, `f1_weighted`) |
| `output.save_backbone` | `false` | copy ESM-2 into the model folder for offline use |

If a setting is missing (or `null`) in both the command line and `config.yaml`, the default above is used. Text choices such as `pooling` and `selection_metric` are not case-sensitive (`MCC` = `mcc`). Misspelled setting names in `config.yaml` are reported as warnings.

If something is wrong (a missing file, an invalid setting), the scripts stop with a short message. Set `ESM2CLF_DEBUG=1` to see the full technical details.

## Choosing the ESM-2 model size

| Model | Parameters | Speed | When to use |
|---|---|---|---|
| `facebook/esm2_t6_8M_UR50D` | 8M | fastest | first experiments, CPU, large datasets |
| `facebook/esm2_t12_35M_UR50D` | 35M | fast | good default on a GPU |
| `facebook/esm2_t30_150M_UR50D` | 150M | moderate | when the small models plateau |
| `facebook/esm2_t33_650M_UR50D` | 650M | slow | best representations; needs a large GPU |

Larger models usually give better representations, especially for subtle distinctions. A good habit is to start with 8M, then check whether 35M or 150M improves MCC on your data:

```bash
python train.py --config config.yaml --model facebook/esm2_t12_35M_UR50D --out results/familyX_35M
```

## Worked example: is ESM-2 good at recognising family X?

1. **Collect positives:** sequences of family X (from Pfam/InterPro, a curated database such as mobileOG-db, or your own annotations). Label them `familyX`.
2. **Collect negatives:** proteins that are *not* family X, ideally including look-alikes (proteins from related families, or with similar length and domains). Label them `other`. Hard negatives make the test meaningful.
3. **Cluster and split** all sequences by identity (e.g. MMseqs2 at 50%) and assign whole clusters to train / validation / test (for example 70/15/15).
4. **Train:**
   ```bash
   python train.py --train train.fasta --val val.fasta --test test.fasta --out results/familyX
   ```
5. **Read the results** in `results/familyX/`:
   - **MCC** is the headline number (1 = perfect, 0 = no better than chance).
   - The **confusion matrix** shows whether errors are missed family members (false negatives) or false alarms.
   - In `predictions_test.csv`, sort by confidence and inspect the most confident mistakes; they are often mislabelled or borderline sequences.
6. **Compare** pooling methods (`--pooling cls` vs `--pooling mean`; nearly free thanks to the cache), model sizes, or a stricter clustering threshold, to see how robust the result is.

[docs/interpreting_results.md](docs/interpreting_results.md) explains what good and bad results look like.

## Testing the installation

```bash
python tests/run_tests.py
```

Runs 35 checks in 2–4 minutes on a CPU, without internet: it builds a tiny randomly initialised ESM-2 and checks, among other things, that `cls` pooling reproduces Hugging Face's `EsmForSequenceClassification` exactly, that mean pooling ignores special tokens and padding, that the cache is reused correctly, that results are reproducible, and that `predict.py` reproduces the training predictions. It tests the code, not the quality of real ESM-2.

## Requirements

- Python 3.9 or newer
- PyTorch 2.1 or newer (a GPU is strongly recommended for computing embeddings of more than ~10,000 sequences; training the head is fast either way)
- Hugging Face `transformers` 4.46 or newer

Tested combinations (all run with `python tests/run_tests.py`):

| Python | PyTorch | transformers |
|---|---|---|
| 3.13 | 2.14 | 4.46.3 and 5.19 |
| 3.9.6 | 2.8 | 4.57 (independent check, earlier version of the code) |

Install with `pip install -r requirements.txt`. For GPU support, install the PyTorch build that matches your CUDA version first (see <https://pytorch.org/get-started/locally/>).
